> هذا التقرير يصف ما فُحص وما أُصلح وما بقي. **لا يعني أن التطبيق «جاهز للإنتاج»**:

## 2. أمان PIN

| المتطلب | التنفيذ |
|---|---|
| لا يُحفظ نصًا | PBKDF2-HMAC-SHA256، 120,000 تكرار، ملح عشوائي 16 بايت لكل رمز، ناتج 32 بايت |
| المقارنة | زمن ثابت (`constantTimeEquals`)، في isolate منفصل |
| التخزين | `flutter_secure_storage` (مشفّر بمفتاح Android Keystore)، مفتاحان: `pin.credential` و`pin.attempts` |
| Rate limiting / Lockout | 5 محاولات مجانية، ثم 30 ث ← 1 د ← 5 د ← 15 د ← ساعة لكل محاولة إضافية. يُصفَّر العداد عند النجاح فقط |
| تغيير الساعة | **جديد**: القفل يُقاس بـ `SystemClock.elapsedRealtime` مع `Settings.Global.BOOT_COUNT`؛ تقديم الساعة أو تأخيرها لا يغيّر مدته |
| إعادة تشغيل التطبيق | العداد والقفل محفوظان في التخزين الآمن |
| إعادة تشغيل الجهاز | القفل الجاري يُحسب بساعة الجهاز (بحد أقصى مدته الأصلية)، ثم يُربط بالإقلاع الجديد فلا تفيد تغييرات الساعة بعده |
| تلف سجل المحاولات | يُعامل كـ 4 محاولات فاشلة، لا كصفر |
| السجلات والشبكة | الـ PIN لا يمر بأي `Log` ولا `AppLogger` ولا القناة الأصلية، ولا يُرسل لأي خادم (لا يوجد خادم) |
| التصدير | ملف التصدير لا يحوي PIN ولا هاشه (مُختبر) |

**حد متبقٍّ (مُوثّق):** من يعيد تشغيل الجهاز ويقدّم الساعة معًا يستطيع إنهاء قفل واحد مبكرًا. كل محاولة بعدها تفتح قفلًا جديدًا، فتكلّف إعادة تشغيل لكل محاولة. أجهزة لا تُظهر `BOOT_COUNT` (نادرة، API 24+) تعود إلى ساعة الجهاز فقط.

اختبارات (`test/features/pin_test.dart`):
- PIN خاطئ
- 50 محاولة تخمين: 4 رفض + 46 قفل
- تقديم الساعة يومين: القفل باقٍ
- تأخير الساعة لا يطيل القفل
- إعادة تشغيل التطبيق
- إعادة تشغيل الجهاز مع إعادة الربط
- غياب الساعة monotonic
- سجل المحاولات لا يحوي الرمز

## 3. تصنيف التخزين

| الفئة | البيانات | المكان | الحماية |
|---|---|---|---|
| **Secrets** | هاش PIN + الملح، عداد المحاولات | `flutter_secure_storage` (namespace `safeguard_secure`) | مشفّر بمفتاح Keystore |
| **Secrets** | مفتاح HMAC للأحداث والذاكرة المؤقتة | Android Keystore (`safeguard.event_hmac.v1`) | غير قابل للتصدير. **جديد** |
| **Sensitive** | قوائم المستخدم (حظر/سماح)، الكلمات المحظورة، التطبيقات المحمية | SQLite في مجلد التطبيق الخاص | صندوق التطبيق (sandbox)، مستبعد من النسخ الاحتياطي |
| **Logs** | سجل الحظر: وقت، فئة، مصدر، إجراء، ثقة، والموضوع (النطاق المحجوب أو اسم التطبيق المحمي أو هاش 32 بت لنص البحث) | SQLite `block_events` | 7/30 يومًا أو لا يُحفظ، وحد 10,000 صف |
| **Logs** | إحصاءات الذكاء الاصطناعي وبلاغات الحظر الخاطئ (فئة + ثقة مقرّبة، دون محتوى) | SQLite | تُمسح مع السجل |
| **Preferences** | الوضع، الفئات، البحث الآمن، إعدادات الذكاء الاصطناعي، المظهر، قفل التطبيق، مدة السجل | SharedPreferences (`sg.*` في Flutter، `safeguard_protection` في Kotlin) | لا أسرار فيها |
| **Assets** | النموذج النصي، القوائم المضمّنة | داخل APK | SHA-256 يُتحقق منه قبل الاستخدام |

لا توجد أسرار في الكود أو git أو السجلات. ملفات التوقيع (`key.properties`، `*.jks`، `*.keystore`) في `.gitignore`.

## 4. قاعدة البيانات

| البند | الحالة |
|---|---|
| Parameterized queries | كلها `?`، حتى `IN (…)` تُبنى بعدد العلامات فقط. بحث القواعد يهرّب `%` و`_` |
| Validation | النطاقات تُطبّع وتُتحقق قبل الإدخال (`UserRules` ← `INVALID_DOMAIN`)، والكلمات 3 أحرف على الأقل و5 كلمات كحد أقصى، والفئات من enum |
| Indexes | `idx_rules_domain`، `idx_rules_source_action`، `idx_events_ts` (تم التحقق بـ EXPLAIN في المرحلة 5) |
| Migrations | v1→v4 خطوة خطوة دون حذف بيانات. **جديد**: downgrade يعيد إنشاء المخطط |
| Corruption | معالج SQLite الافتراضي يحذف الملف التالف، ثم تُعاد تعبئة القواعد المدمجة (القوائم المضمّنة في APK لا تتأثر). `isHealthy()` يظهر في صحة الحماية |
| Backup | `allowBackup=false`، و`dataExtractionRules` تستبعد كل النطاقات من السحابة والنقل بين الأجهزة |
| ما لا يُخزَّن | كلمات مرور، رسائل، لقطات شاشة، صور، نصوص بحث، النطاقات المسموح بها، سجل التصفح الكامل |

## 5. أمان VPN: ما يراه التطبيق وما لا يراه

VPN محلي بالكامل: عنوان TUN داخلي، و**مسار واحد فقط هو عنوان DNS الافتراضي**. لذلك لا تمر عبر التطبيق إلا حزم DNS. بقية حركة المرور تذهب مباشرة إلى الشبكة ولا يراها SafeGuard.

| يرى | لا يرى |
|---|---|
| اسم النطاق المطلوب في استعلام DNS ونوعه (A/AAAA/…) | محتوى الصفحات والرسائل والصور والفيديو |
| | أي تطبيق أرسل الاستعلام (الحزمة لا تحمل هويته) |
| | عناوين URL الكاملة ومساراتها ومعاملاتها |
| | كلمات المرور، الكوكيز، رؤوس HTTP |
| | حركة HTTPS/QUIC نفسها |
| | استعلامات DNS المشفّرة التي يجريها تطبيق بنفسه (DoH داخل المتصفح) |

- **ما يُحفظ:** النطاق المحجوب فقط (مع الوقت والفئة) في السجل المحلي. الاستعلامات المسموح بها لا تُحفظ إطلاقًا.
- **التوجيه:** الاستعلامات المسموح بها تُرسل إلى خوادم DNS الخاصة بالشبكة الحالية كما كانت ستُرسل دون التطبيق، عبر مقبس محمي (`protect`). إذا لم تُعلن الشبكة أي خادم، يُستخدم 1.1.1.1 ثم 9.9.9.9 كاحتياط. هذا هو الاتصال الخارجي الوحيد، وليس خادمًا لـ SafeGuard.
- **لا خادم VPN خارجي، ولا بيانات اعتماد**، ولا تعطيل لـ VPN آخر: Android يسمح بـ VPN واحد، والتطبيق يعرض الحالة ولا يلتفّ عليها.
- **السجلات:** رسائل ثابتة فقط («tun read failed: IOException»). لا نطاقات ولا محتوى حزم.
- **دورة الحياة:** onRevoke/stop يغلقان TUN والمقابس. الاستعادة التلقائية محدودة (3 محاولات كل 10 دقائق) ولا تعمل دون موافقة أو في وضع الأمان.
- **الأخطاء:** تصل إلى Flutter كرموز (`PERMISSION_REQUIRED`، `INVALID_ARGUMENT`، `INTERNAL` + اسم الصنف)، دون رسائل قد تحوي مدخلات.

## 6. الخصوصية حسب التصميم

- **لا يجمع:** كلمات مرور، رسائل، صور، جهات اتصال، سجل تصفح كامل، تسجيلات شاشة أو صوت.
- **لا يرسل شيئًا:**
  - لا حساب، ولا تحليلات، ولا تقارير أعطال، ولا SDK طرف ثالث يتصل بالشبكة.
  - الاعتماديات: `crypto`، `flutter_secure_storage`، `go_router`، `shared_preferences`.
- **البحث:** النص يُطبَّع ويُفحص في الذاكرة. يُحفظ هاش 32 بت (بمفتاح Keystore) + الفئة، لا النص.
- **Accessibility:** اسم حزمة التطبيق في المقدمة فقط (القسم 9).

## 7. خصوصية الذكاء الاصطناعي

- التصنيف على الجهاز فقط. النموذج النصي داخل APK. الصور تُفحص في الذاكرة ولا تُحفظ (لا يوجد نموذج صور مضمّن حاليًا).
- `CloudClassifierAdapter` موجود كواجهة فقط:
  - يتطلب موافقة صريحة وناقلًا مشفّرًا.
  - **لا يوجد ناقل ولا يُسجَّل في الإصدار**، والافتراضي غير مفعّل.
  - إن أُضيف مستقبلًا فيجب أن يكون اختياريًا، بموافقة صريحة، ومشفّرًا، وموثقًا، وقابلًا للحذف.
- الذاكرة المؤقتة: مفاتيحها HMAC (بمفتاح Keystore) للمحتوى، وتحفظ الدرجات فقط. تُمسح مع السجل وعند حذف البيانات.

## 8. الأذونات

| الإذن | لماذا | الميزة | هل يمكن إزالته؟ |
|---|---|---|---|
| `INTERNET` | توجيه استعلامات DNS المسموح بها إلى خادم الشبكة | فلترة DNS | لا: بدونه تنقطع أسماء النطاقات |
| `ACCESS_NETWORK_STATE` | معرفة خوادم DNS للشبكة الحالية وتغيّرها | فلترة DNS، صحة الحماية | لا |
| `RECEIVE_BOOT_COMPLETED` | إعادة تشغيل الحماية بعد إقلاع الجهاز (إن كانت مفعّلة وموافقة VPN قائمة) | استمرارية الحماية | ممكن، لكنه يُضعف الحماية. يُفضّل «VPN دائم التشغيل» في Android |
| `BIND_VPN_SERVICE` (للخدمة) | يضمن أن النظام وحده يربط الخدمة | VPN | لا |
| `BIND_ACCESSIBILITY_SERVICE` (للخدمة) | يضمن أن النظام وحده يربطها | حماية التطبيقات | لا (الخدمة نفسها اختيارية) |
| `<queries>` LAUNCHER/HOME/VIEW https | عرض التطبيقات القابلة للتشغيل لاختيار المحمية منها | حماية التطبيقات | بدلًا من `QUERY_ALL_PACKAGES` الأوسع |

**غير مطلوبة ولا مستخدمة:**
- `QUERY_ALL_PACKAGES`، `READ_EXTERNAL_STORAGE`، `CAMERA`، `READ_CONTACTS`، `SYSTEM_ALERT_WINDOW`، `PACKAGE_USAGE_STATS`، `POST_NOTIFICATIONS`، الموقع
- الصور تُختار عبر منتقي المستندات في النظام (`ACTION_OPEN_DOCUMENT`) والتصدير عبر SAF (`CREATE_DOCUMENT`)، فلا حاجة لأذونات تخزين

Flutter يضيف `INTERNET` تلقائيًا في debug فقط، وهو موجود أصلًا.

## 9. Accessibility

| السؤال | الجواب |
|---|---|
| لماذا؟ | حماية التطبيقات: منع فتح تطبيق يختاره المستخدم. لا بديل في Android بلا صلاحيات إدارة الجهاز |
| ماذا يقرأ؟ | حدث `TYPE_WINDOW_STATE_CHANGED` فقط، و`canRetrieveWindowContent=false`: **اسم حزمة التطبيق في المقدمة**، لا نصوص ولا محتوى شاشة |
| هل يُخزّن؟ | فقط إذا كان التطبيق محميًا وحُجب: اسم الحزمة + الوقت في السجل المحلي |
| هل يُرسل؟ | لا |
| هل يمكن تقليله؟ | هو بالفعل في الحد الأدنى: حدث واحد، بلا محتوى نافذة، بلا gestures، بلا overlay. الخدمة معطلة ما لم يفعّلها المستخدم بعد إفصاح داخل التطبيق |
| كلمات مرور/بنوك/رسائل؟ | لا يمكنه قراءتها: الإعداد يمنع الوصول لمحتوى النوافذ على مستوى النظام |

## 10. أمان الشبكة

- `usesCleartextTraffic=false`. لا نقاط HTTP أو HTTPS في الكود (اختبار آلي). لا مفاتيح API ولا أسرار في APK.
- الاتصال الشبكي الوحيد هو DNS إلى خادم الشبكة (UDP 53، كما يفعل النظام دون التطبيق).
- **خادم مستقبلي (لم يُضف):** إن احتاج المشروع خادمًا (تحديث القوائم مثلًا):
  - HTTPS فقط مع Network Security Config يمنع cleartext، وتثبيت مفتاح عام (pinning) مع مفتاح احتياطي.
  - تحديثات القوائم ملفات ثابتة موقّعة (Ed25519) يتحقق التطبيق من توقيعها وهاشها قبل الاستبدال، فلا يُثق بالخادم وحده.
  - لا هوية للمستخدم ولا معرّف جهاز. الطلبات GET بلا ملفات تعريف.
  - لا أسرار في APK. أي مصادقة تكون برمز قصير العمر يصدره الخادم.
  - لا رفع لمحتوى المستخدم إلا بموافقة صريحة لكل عملية (مثل السحابة في القسم 7).

## 12. الاحتفاظ بالبيانات

- الإعدادات ← الخصوصية ← **مدة الاحتفاظ بالسجل**: 7 أيام / 30 يومًا (افتراضي) / لا يُحفظ سجل.
- **«لا يُحفظ سجل»:** لا تُكتب أي أحداث. تبقى الحماية كما هي، ويبقى عدّاد الحظر الإجمالي فقط. تبقى الإحصاءات فارغة.
- التقصير يحذف فورًا ما هو أقدم (بعد تأكيد)، والتنظيف الدوري يتبع الإعداد الحالي، ويُطبّق أيضًا عند بدء التطبيق.
- أي تغيير يتطلب PIN: السجل هو ما يراجعه ولي الأمر.
- «لا يُحفظ» يعني عدم الاحتفاظ لا «الاحتفاظ للأبد»، لأن الاحتفاظ غير المحدود يخالف هدف تقليل البيانات.

| مسح سجل الحماية | الأحداث، الإحصاءات، البلاغات، الذاكرة المؤقتة للذكاء الاصطناعي | تأكيد + PIN |
| إعادة ضبط الحماية | الإعدادات إلى الافتراضي الآمن (القوائم والسجل باقية) | تأكيد + PIN |
| حذف كل البيانات | كل شيء: PIN، الإعدادات، القوائم، الكلمات، التطبيقات، السجل، وتدوير مفتاح HMAC في Keystore (**جديد**) | تأكيد + PIN |
| تغيير مدة السجل | الأقدم من المدة الجديدة | تأكيد عند التقصير + PIN |
| تصدير الإعدادات | لا يحذف. الملف لا يحوي PIN ولا سجلًا | PIN، ويختار المستخدم مكان الحفظ |

## 14. النسخ الاحتياطي

`android:allowBackup="false"` و`fullBackupContent="false"`. `data_extraction_rules.xml` تستبعد root/file/database/sharedpref/external للسحابة ولنقل الجهاز (Android 12+).

مفاتيح Keystore لا تُنسخ احتياطيًا بطبيعتها. فلا تتسرّب بيانات PIN أو المفاتيح أو السجل أو بيانات الذكاء الاصطناعي أو إعدادات VPN.

## 15. بناء الإصدار

التفاصيل في [`RELEASE.md`](RELEASE.md).

| البند | الحالة |
|---|---|
| R8 / ProGuard | `isMinifyEnabled`، `isShrinkResources`، `proguard-android-optimize.txt` + `proguard-rules.pro` |
| التوقيع | من `android/key.properties` (خارج git). بدونه يُوقّع بمفتاح debug للتجربة المحلية فقط |
| الإصدار | `1.5.0+6` في `pubspec.yaml` (versionName/versionCode) |
| Debug | `isDebuggable=false`. بيانات اختبار القواعد تُزرع في debug فقط وتُحذف إن وُجدت في release |
| السجلات | `Log.v/d/i` تُزال. `AppLogger` صامت |
| Mock classifier | في `src/test` فقط، غير موجود في APK |
| Endpoints تطوير | لا يوجد |
| Build flavors | **لم تُضف:** نسخة واحدة بلا خوادم لا تحتاج dev/prod. وإضافتها تغيّر أوامر `flutter run` دون فائدة. تُضاف حين يوجد خادم |

## ما يلزم قبل النشر (لم يُتحقق منه هنا)

1. `flutter build appbundle --release` بمفتاح حقيقي، والتأكد من أن R8 لا يكسر شيئًا. تشغيل الإصدار على جهاز والتحقق من الحماية والبحث والتطبيقات والذكاء الاصطناعي.
2. `cd android && ./gradlew test`: اختبارات Robolectric لقاعدة البيانات لم تُشغّل في بيئة التطوير.
3. اختبارات يدوية على الجهاز لـ PIN:
   - تقديم الساعة أثناء القفل
   - إعادة تشغيل الجهاز أثناء القفل
4. تغيير مدة السجل إلى 7 أيام ثم «لا يُحفظ»: التأكد من أن السجل يُفرغ.
5. تحديث التطبيق من 1.4.0: التأكد من حذف `event_hash_key` من SharedPreferences.
6. سياسة الخصوصية ونموذج Data safety في Google Play، ونموذج إفصاح VpnService وAccessibility (Play يتطلب مراجعة لاستخدامهما).
7. تغيير `applicationId` من القيمة المؤقتة `com.safeguard.app` إن لزم.
